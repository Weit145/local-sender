# Local Sender

Десктопное приложение для поиска устройств и обмена сообщениями в локальной
сети. Go + Wails 3 + React + TypeScript. Интерфейс на русском в единственном терминальном стиле: почти чёрный фон,
приглушённый зелёный текст, моноширинный шрифт и прямоугольные панели.
Есть входящие запросы, поиск и подключение по IP.

## Desktop: быстрый старт

Нужны Go 1.27.3 (либо совместимая исправленная версия Go 1.26+), Node.js 24
и системные зависимости Wails.

Ubuntu / Debian с GTK4 и WebKitGTK 6:

```sh
sudo apt-get install build-essential pkg-config libgtk-4-dev libwebkitgtk-6.0-dev
```

Windows: установите Microsoft Edge WebView2 Runtime, если его нет в системе.
macOS: установите Xcode Command Line Tools через `xcode-select --install`.
Подробнее: [системные зависимости Wails](https://wails.io/quick-start/installation/).

Из корня проекта:

```sh
npm --prefix frontend ci
npm --prefix frontend run desktop:run
```

Команда собирает интерфейс и запускает настоящее окно Wails. Отдельная
установка Wails CLI не нужна: точка входа использует Go API Wails.

В приложении выберите сетевой интерфейс и нажмите «Найти устройства».
На втором устройстве тоже должен быть открыт Local Sender. Можно подключиться
по IP и TCP-порту, затем принять запрос на втором устройстве и открыть чат.
Приложение одновременно принимает и создаёт подключения.

Если автопоиск недоступен, проверьте выбранный интерфейс и разрешения
брандмауэра для TCP 8080 и UDP 9999 либо используйте подключение по IP.

## Сборка для своей платформы

```sh
npm --prefix frontend run desktop:build
```

Результат:

- Linux: `bin/local-sender` (для запуска нужны GTK4 и WebKitGTK 6).
- Windows: `bin/local-sender.exe` (для запуска нужен WebView2).
- macOS: `bin/Local Sender.app` (с локальной ad-hoc-подписью).

Сборку выполняйте на целевой ОС. Workflow `.github/workflows/desktop.yml`
проверяет код и создаёт артефакты для Linux, Windows и macOS. Публикация
не настроена. Для публичной дистрибуции macOS потребуется собственная подпись
и notarization; текущая сборка предназначена для разработки и проверки.

## Разработка интерфейса

Для горячего обновления React запустите два терминала:

```sh
# Терминал 1
npm --prefix frontend run dev

# Терминал 2: bash / zsh
FRONTEND_DEVSERVER_URL=http://127.0.0.1:5173 go run ./cmd/desktop
```

PowerShell во втором терминале:

```powershell
$env:FRONTEND_DEVSERVER_URL = "http://127.0.0.1:5173"
go run ./cmd/desktop
```

Перед первым запуском выполните `npm --prefix frontend run build`, чтобы
подготовить встраиваемые ресурсы. Сам по себе Vite в браузере не запускает
сетевой Go-бэкенд; для работы используйте окно Wails.

## Настройки и данные

Сетевые параметры сохраняются в `local-sender/settings.json` внутри
системной папки конфигурации (`os.UserConfigDir`). Путь можно переопределить
переменной `LOCAL_SENDER_CONFIG` — это удобно для двух экземпляров на одной
машине. Для них укажите разные TCP- и UDP-порты; адрес поиска можно направить
на UDP-порт второго экземпляра.

Повторное сохранение прежних параметров сохраняет подключения. Изменение
сетевых параметров завершает
сессии и очищает переписку. Если новый порт занят или файл настроек не удаётся
сохранить, приложение пытается вернуть прежнюю конфигурацию и сообщает ошибку.

История хранится только в памяти: до 1000 последних сообщений суммарно.
Она очищается при перезапуске приложения или сети. Галочка возле исходящего
сообщения означает передачу сетевому писателю, а не подтверждение доставки.

Текущий протокол передаёт текстовые строки и не реализует шифрование,
передачу файлов или совместимость с протоколом других приложений LocalSend.

## Архитектура

```text
cmd/desktop/          окно и жизненный цикл Wails
frontend/src/         React, терминальный стиль, типизированный API Wails
internal/desktop/    адаптер, настройки, отмена операций, история сеанса
internal/usecase/    сценарии и состояние приложения
internal/connect/    TCP-подключения и обмен строками
internal/discovery/  UDP-поиск
internal/cli/        консольный пример
```

`internal/desktop` не зависит от GUI и тестируется без дисплея. Он читает
события usecase и отправляет снимки состояния в Wails. Снимки имеют поколение
сервиса и монотонный номер ревизии; UI игнорирует устаревшие обновления.

## Проверки

```sh
npm --prefix frontend run build
go test -race ./...

# Браузерная проверка двух настоящих Wails-бэкендов
npm --prefix frontend exec -- playwright install chromium
npm --prefix frontend run test:e2e
```

На Windows для `-race` потребуется поддерживаемый C-компилятор; обычная проверка:
`go test ./...`. На Linux полная проверка desktop-пакета требует заголовков
GTK/WebKit, как и нативная сборка.

E2E-тесты сами собирают Wails в режиме `server` с `CGO_ENABLED=0` и запускают
два процесса на loopback-портах 19450–19451, 19460–19461, 19470–19471 с временными
настройками. Они проверяют единственный терминальный стиль, сохранение настроек, размеры
окна, клавиатурную работу диалога,
поиск, принятие и отказ, сообщения в обе стороны и отключение. Такой режим
служит проверке Wails-моста; нативный desktop остаётся основной точкой входа.

## Консольный пример

```sh
go run ./cmd/messager -tcp :8080 -udp :9999
```

`cmd/app` запускает тот же пример. Команды:

```text
interfaces
discover 192.168.1.10
devices
connect 192.168.1.20:8080
pending
accept <request-id>
reject <request-id>
connections
send <connection-id> Привет!
disconnect <connection-id>
quit
```

## API usecase

- `Start(ctx)` ждёт открытия TCP и UDP. `Stop()` отменяет задачи и ждёт их
  завершения; повторный вызов безопасен. Для перезапуска сначала вызовите `Stop`.
- `ListInterfaces()`, `DiscoverDevices(ctx, localIP)`, `ListDevices()` работают
  с интерфейсами и поиском. Собственный таймаут поиска — нормальное завершение;
  отмена вызывающего контекста возвращается ошибкой. Параллельный поиск запрещён.
- `Connect(ctx, addr)` ждёт решения собеседника. После успеха соединение живёт
  до `Disconnect` или `Stop`, независимо от контекста вызова `Connect`.
- `ListPendingRequests()`, `AcceptConnection(id)`, `RejectConnection(id)`
  управляют входящими запросами; ID запроса совпадает с ID соединения.
- `ListConnections()` возвращает копию состояния, включая завершённые сессии.
- `SendMessage(ctx, id, text)` передаёт одну строку писателю. Ошибки записи
  приходят через `Events()`. Подтверждения доставки протокол не содержит.
- `Events()` — поток для одного потребителя с очередью из 256 событий.
  Заполненная очередь приостанавливает производителей; отмена освобождает их.
  Поток сохраняется при перезапуске usecase и не закрывается. При остановке
  часть событий может быть пропущена; актуальное состояние доступно в `List…`.

## Визуальный стиль

Один стиль для всех ОС; выбор темы и зависимость от системной светлой/тёмной
схемы удалены. Старое поле `theme` в настройках игнорируется, сетевые параметры
при этом сохраняются. Прямоугольные панели, один зелёный акцент и статичная
слабая текстура CRT без мерцания. Движение индикаторов отключается при
`prefers-reduced-motion`.

Ориентиры: [Retro Chat](https://retrochat.nl/),
[Terminal / Hacker UI](https://www.artifx.dev/ui-styles/terminal-hacker-ui),
[Terminal UI Theme](https://github.com/rampstackco/terminal-ui-theme).
